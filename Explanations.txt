Tesselater 2.0 — technical notes
================================

Package layout
--------------
tesselater/config.py       Printer + material + support weights
tesselater/mesh_io.py      Load / seat / rotate meshes (no import-time I/O)
tesselater/geometry.py     COM, first-layer footprint, tip-circle containment
tesselater/results.py      Shared AnalysisResult / MeshActor
tesselater/analysis/       Heuristics (warping, toppling, shrinkage, …)
tesselater/support/        Tip map → candidates → score → recommendation
tesselater/pipeline.py     Headless PrintabilityReport
tesselater/ui/             main_window (shell), actions, viewers
main.py                    Entry point  (Curses.py still launches main)
tests/                     pytest

Support optimization (stage B)
------------------------------
1. Overhang faces (same angle rule as analysis/overhangs).
2. Cluster face centers on an XY grid (cluster_pitch_mm) → tip points.
3. Candidates:
   - dense_pillars: one column per tip (flat tips)
   - sparse_pillars: merge tips within sparse_merge_radius_mm
   - tree: larger merge + thicker trunks, point tips (branch volume deferred)
4. Cost J = w_t·(T/60) + w_v·(V/1000) + w_c·A_contact + w_s·scar_score
   scar_score ≈ 0.6·A_scar + 0.4·peel ; peel uses material tip_bond and tip style.
   T ≈ V/(line_width·layer_height·speed) + travel/travel_speed.
5. Pick feasible candidate with minimal J. Export solids via support/export.py.
6. Orientation search (optimize/orientation.py): grid of rx/ry/(rz) poses,
   J_pose = support_cost + unstable_penalty·[bad topple] + 0.05·tips.
7. CLI: report | optimize | export-supports | materials | gui
   Config/materials: config.example.toml, materials/*.toml

Run:  python main.py
Config: edit DEFAULT_CONFIG in tesselater/config.py (or construct AppConfig).


Geometric evaluation (mathematical resolution)
----------------------------------------------
Older versions used the mean of mesh *vertices* as center of mass, and tested
whether a tip-stability circle sat inside the *axis-aligned bounding box* of
the first layer. Both are wrong for general STLs.

(1) Volumetric center of mass (closed triangular polyhedron, uniform density)

    Decompose the solid into tetrahedra from the origin to each oriented
    surface triangle (a, b, c). With the scalar triple product

        τ_i = a · (b × c)
        V   = (1/6) Σ τ_i

    the center of mass is

        C = Σ τ_i (a + b + c) / (4 Σ τ_i)
          = Σ τ_i (a + b + c) / (24 V)

    If |V| is negligible (open / non-manifold mesh), fall back to the
    area-weighted shell centroid:

        C = Σ A_i c_i / Σ A_i ,   c_i = (a+b+c)/3 ,   A_i = (1/2)||(b-a)×(c-a)||

(2) First-layer contact footprint

    Take all vertices in the slab z ∈ [z_min, z_min + h_layer], project to XY,
    and form the convex hull H = conv(points). Contact area is the shoelace
    area of H — not Δx·Δy of the AABB.

(3) Tip-stability circle containment

    Under a quasi-static lean of angle θ about a horizontal axis, the vertical
    through the COM meets the bed on a circle of radius

        r = H_mesh · tan(θ)

    centered at the COM's XY projection. If that entire circle lies inside H
    (convex point-in-polygon on sampled ring points), every lean ≤ θ keeps the
    support force inside the contact set. This is a *conservative* criterion
    (convex hull ⊇ true contact polygon).

(4) Dimensionless stability margin

        m = Area(H) / (H_mesh · d²)

    with d = nozzle diameter. Compared to printer.stability_margin_threshold
    (default 50). Replaces the previous dimensional magic number 9.67.


Other analysis notes
--------------------
Overhangs: face normal angle from +Z exceeds (180° − overhang_angle_deg).
For the default 45° rule that means angle(normal, +Z) > 135° (downward
faces past a 45° lean from vertical). Vertical walls (≈90°) are not flagged.

Roughness: faces in shallow stair-step (2°–45°) or steep (135°–178°) bands;
colors stored in cell_data['SurfaceRoughness'] and rendered with rgb=True.

Shrinkage: isotropic scale 1 − shrinkage_fraction from the material table.
The old Outer_volume algebra cancelled back to the same constant; that
indirection is removed. heat_warped_volume = V·CTE·ΔT remains a diagnostic.

Warping: empirical tendency from speed / line-width vs quality speed, scaled
by shrinkage. Visualization pulls first-layer points toward a point above the
base centroid (qualitative, not a thermal FEM).

Small details: cell area < nozzle_size² · microstepping (mm²).

Watertight meshes: strongly recommended. Non-manifold STLs degrade COM and
volume terms; the UI warns when open edges / non-positive volume are detected.

Supports: toppling assumes conventional supports for overhangs; it does not
simulate custom support strategies.

References / inspiration: Will-It-Print and the warping / shrinkage literature
linked from README.md.
